# LWC in Agentforce

This repo is a demo for Custom Lightning Types in Agentforce.  
This is linked to a talk delivered several times, including [Dreamforce 2025](https://speakerdeck.com/fabientaillon/dreamforce-2025-improve-agent-interactions-with-custom-lwcs-in-agentforce?slide=2).  
To create a demo Scratch Org, just install [texei-sfdx-plugin](https://github.com/texei/texei-sfdx-plugin) and run `./createScratchOrg.sh`.

## Notes on the Agent Script deployment order

The agent is defined with Agent Script in `force-app/main/default/aiAuthoringBundles/Restaurant_Agent`. A few things are worth knowing about how it deploys:

- Deploying the `AiAuthoringBundle` only stores it in the org: the agent (Bot) itself is created when running `sf agent publish authoring-bundle`. The script uses `--skip-retrieve`, otherwise the CLI pulls back org-specific generated metadata (planner bundles with record IDs, a `NextGen_<botId>` permission set, etc.) that shouldn't live in source control.
- The `Restaurants_Management` permission set grants access to the agent via `<agentAccesses>`, so it can only be deployed once the agent exists. That's why it lives in `post-push-source/` (deployed after `sf agent publish`) instead of `force-app/`.
- The `Search_Restaurants` action is defined entirely in the `.agent` file (`target: "apex://RestaurantService"`, no `source:`), so there is no `GenAiFunction` in source: publishing the agent generates the action inside the agent. The output type (`complex_data_type_name`) is the Lightning type that decides the rendering: `c__restaurantResponse` (LWC) or `c__restaurantHxlResponse` (HXL widget). Each publish creates a new inactive version, so run `sf agent activate` afterwards.

## HXL widgets and MCP

The same Apex result can also be rendered by a Headless Experience Layer (HXL) widget, in Agentforce and in MCP clients such as Claude or ChatGPT. Everything is additive to the LWC demo: `uiWidgets/restaurantList` and `uiWidgets/restaurantSlots` are the widgets (HXL is beta, API 67+), and the scratch org definition enables it through `uiWidgetSettings.hxlEnabled`. On a non-scratch org, turn on Setup → Headless Experience Layer Settings before deploying.

### Switching the Agentforce rendering between LWC and HXL widget

The `Search_Restaurants` action returns the same Apex result in both cases. The rendering is decided by the output type declared in `force-app/main/default/aiAuthoringBundles/Restaurant_Agent/Restaurant_Agent.agent`:

- `complex_data_type_name: "c__restaurantResponse"` renders the LWC `restaurantDetails` (default).
- `complex_data_type_name: "c__restaurantHxlResponse"` renders the HXL widget `restaurantList`.

Change that line, then redeploy the bundle and republish the agent. Each publish creates a new inactive version, so activate it, and start a new conversation to see the change:

```bash
sf project deploy start --source-dir force-app/main/default/aiAuthoringBundles
sf agent publish authoring-bundle --api-name Restaurant_Agent --skip-retrieve
sf agent activate --api-name Restaurant_Agent
```

### Using the MCP server from Claude

The Salesforce side is fully handled by `createScratchOrg.sh`: the hosted MCP server (`mcpServerDefinitions/restaurantsearchserver`, exposing the Apex actions as tools with their widgets) is deployed and activated, the External Client App `HXL_Claude_MCP` is deployed (PKCE, no secret, consumer key generated by the org), and the script prints the server URL at the end.

Connecting Claude is a manual step on Claude's side, and its UI may change, so it isn't detailed here. What you need: the server URL printed by the script, and the consumer key of the External Client App (Setup → External Client App Manager → HXL Claude MCP → OAuth Settings) as OAuth client ID, with no client secret. Then add a custom connector in Claude with those two values, log in to the org when prompted, and ask for restaurants in a city: the result is rendered by the same HXL widget. The External Client App can take up to 30 minutes to be accepted by `api.salesforce.com` after deployment. Other MCP clients can use the same server; only the callback URL of the External Client App would need to match the client.
